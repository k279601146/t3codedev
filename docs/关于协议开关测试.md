可以这样测，关键是要满足两个条件：**引擎开启 `apply_patch_streaming_events`**，并且 **模型真的走 `apply_patch` 工具**。普通 PowerShell/Python 写文件不会产生 `item/fileChange/patchUpdated`，只会在最终 checkpoint diff 里看到文件变化。

**先打开协议开关**

你当前这个文件里还没有开：

`C:\Users\Administrator\.bahew\agent-data\config.toml`

在 `[features]` 下面加：

```toml
apply_patch_streaming_events = true
apply_patch_freeform = true
```

注意：桌面端可能会在启动时重写托管配置。最稳的方式是把同样两行加到源码的托管引擎配置生成处：

`D:\workspace\t3codedev\packages\shared\src\commercialEngine.ts`

也就是 `[features]` 里和 `plugins = true`、`apps = true` 放一起。然后重启客户端/后端，让新的 `ai-engine.exe` 进程读取配置。

**客户端测试提示词**

用一个干净测试目录，新开任务，发第一轮：

```text
请只使用 apply_patch 工具完成，不要使用 PowerShell、Python、cmd、echo、重定向或脚本命令。
创建文件 patch_probe_create.txt，内容为：
created-by-apply-patch
line-two
```

完成后再发第二轮：

```text
请只使用 apply_patch 工具编辑已有文件 patch_probe_create.txt，不要运行任何 shell 命令。
把 line-two 改成 edited-by-apply-patch，并新增一行 final-line。
```

如果协议链路正常，日志里应该能搜到：

```powershell
Select-String -Path "C:\Users\Administrator\.bahew\userdata\logs\provider\*.log" -Pattern "item/fileChange/patchUpdated","item/started","item/completed"
```

你应该看到 `item/fileChange/patchUpdated`，并且其中有类似：

```json
"changes":[{"path":"patch_probe_create.txt","kind":"add","diff":"..."}]
```

第二轮应该是：

```json
"kind":"update"
```

界面上对应应该显示“已创建 patch_probe_create.txt”和“已编辑 patch_probe_create.txt”，而不是塞进“已运行 X 条命令”里。

如果日志里没有 `item/fileChange/patchUpdated`，先不要看 UI，说明前端根本没收到这类协议事件。常见原因就是：开关没生效、模型没有使用 `apply_patch`、或者当前模型/网关没有暴露 freeform `apply_patch` 工具。
