| BundledEngineConfig 通过环境变量注入配置 | `apps/server/src/provider/BundledEngineConfig.ts` | 使用 `CODEX_MODEL_*` 环境变量，统一走 `wire_api = "responses"` |

## 开发任务分解

### Phase 1：sub2api 网关验证（Day 1 上午）

**目标**：确认 sub2api 对 Claude/Gemini 的 tool_call 格式转换正常

#### 任务 1.1：配置 sub2api 渠道

- 在 sub2api 管理后台配置 Anthropic 渠道（Claude 系列）
- 在 sub2api 管理后台配置 Gemini 渠道
- 配置模型名称映射（`claude-sonnet-4-5` → `claude-sonnet-4-5-20251001` 等）

#### 任务 1.2：curl 验证 tool_call 转换

```bash
# Claude tool_call 验证
curl -X POST ${GATEWAY_URL}/chat/completions \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"model":"claude-sonnet-4-5","messages":[{"role":"user","content":"hello"}],"tools":[{"type":"function","function":{"name":"bash","parameters":{"type":"object","properties":{"cmd":{"type":"string"}}}}}],"stream":true}'

# Gemini tool_call 验证
curl -X POST ${GATEWAY_URL}/chat/completions \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"model":"gemini-2.5-flash","messages":[{"role":"user","content":"hello"}],"tools":[{"type":"function","function":{"name":"bash","parameters":{"type":"object","properties":{"cmd":{"type":"string"}}}}}],"stream":true}'
```

**验收标准**：响应中包含 `tool_calls` 字段，流式 SSE 格式正确。

## 关键架构决策

### 决策 1：不引入新的 Driver

方案文档建议的 `EngineManager` 重构在当前架构中**不需要**。原因：

- `CodexDriver` 已经是模型无关的——它管理的是 codex app-server 进程，不是特定模型
- 模型切换通过 `modelSelection.model` 在 session 级别注入，已有完整路径
- 不需要为 Claude/Gemini 创建独立的 Driver（那是方案文档中"错误理解"部分描述的旧方案）

### 决策 2：模型切换 = 新建 Session（方式 A）

- 用户切换模型时，结束当前 session，创建新 session 并传入新 model
- 不尝试运行时热切换（codex app-server 不支持）
- 这与前端现有的"新建对话"流程一致

### 决策 3：统一使用 `wire_api = "responses"`

- 已在 `commercialEngine.ts` 中配置：`COMMERCIAL_ENGINE_WIRE_API = "responses"`
- sub2api 后端自动适配上游（Responses → Anthropic/Gemini 格式转换）
- codex 侧无需区分模型类型

### 决策 4：模型列表来源

- 主要来源：sub2api `GET /v1/models`（动态，按用户分组/套餐过滤）
- 降级来源：codex 二进制 `--list-models`（静态，仅 OpenAI 模型）
- 前端不硬编码模型列表

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| sub2api Responses API 转换不完整 | Claude/Gemini tool_call 失败 | Phase 1 提前验证；必要时在 sub2api-fork 中修复 |
| codex app-server 不识别非 OpenAI 模型名 | 引擎拒绝启动或使用错误的 tokenizer | 通过 `CODEX_MODEL_CONTEXT_WINDOW` 显式覆盖 |
| 模型列表接口延迟高 | 前端加载慢 | 5 分钟缓存 + 乐观 UI（先显示上次缓存） |
| Gemini 的 tool_call 格式差异大 | Agent loop 中断 | sub2api 侧重点测试多轮 tool_call 场景 |

## 不在本期范围

- 多 Provider Instance 支持（如同时配置两个 Claude 账号）—— 架构已支持，但 UI 和配置流程暂不开放
- 模型级别的用量计费展示 —— 依赖 sub2api 侧的计费接口完善
- 自动降级（某模型不可用时自动切换到备选）—— 后续迭代
