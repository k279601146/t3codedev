# 多模型支持开发计划

更新时间：2026-07-07

本文是 T3 Code 当前多模型接入计划。旧版 sub2api 路线已废弃；后续开发不要再配置或依赖 `D:\workspace\sub2api-fork`。当前 T3 Code 的商业化模型入口是 dev2 薄 OpenAI-compatible 计费代理。

计费、扣费、5 小时窗口、每周窗口、余额、奖励和退款只以 `D:\workspace\dev2_OpenHarness_SaaS\docs\dev2-local-billing-authority.md` 为准。

## 当前架构

T3 Code 客户端只持有：

- dev2 Web 授权入口：`MYIDE_WEB_AUTH_BASE_URL`
- dev2 计费代理入口：`MYIDE_GATEWAY_BASE_URL`
- dev2 签发的 IDE JWT：`MYIDE_IDE_JWT`

T3 Code 不持有真实上游 Base URL 或 API key。`CODEX_OPENAI_BASE_URL`、`OPENAI_BASE_URL`、`CODEX_MODEL_PROVIDERS_*_BASE_URL` 都必须指向 dev2 `/v1`。

dev2 后台 “T3 Code 客户端” 菜单维护专用配置：

- `t3code_openai_base_url`
- `t3code_openai_api_key`
- `t3code_default_model_id`
- `t3code_models_allowlist`
- `t3code_default_max_output_tokens`
- `t3code_max_output_tokens`
- `t3code_upstream_timeout_seconds`

这些配置不能复用 dev2 全局 `openai_base_url` / `openai_api_key`。

## 核心原则

- dev2 不做账号池、多渠道路由或 Claude/Gemini/OpenAI 协议转换。
- dev2 只转发 OpenAI-compatible upstream。
- 第一阶段要求 upstream 支持 T3 Code 主要使用的 `/v1/responses`。
- `/v1/chat/completions` 只作为兼容入口。
- 模型是否可用以 dev2 `/v1/models` 和 `t3code_models_allowlist` 为准。
- 前端模型选择、usage gate、toast 都只是体验层；最终放行或拒绝以 dev2 代理返回为准。

## 请求链路

```text
T3 Code Web/Desktop
  -> ai-engine / codex app-server
  -> CODEX_OPENAI_BASE_URL = dev2 /v1
  -> Authorization: Bearer MYIDE_IDE_JWT
  -> dev2 T3 Code billing proxy
  -> t3code_openai_base_url + t3code_openai_api_key
  -> OpenAI-compatible upstream
```

dev2 在请求前做额度预检，在响应后解析 usage 并写本地账务：

- `ResourceLog`
- `BillingLedgerEntry`
- `BillingAccount`

usage 缺失、上游失败、流式中断或扣费失败时，dev2 fail closed。

## 开发任务

### Phase 1：dev2 模型目录确认

目标：模型选择器只展示 dev2 返回的可用模型。

- 使用 `GET /v1/models` 拉取模型列表。
- 保留 `packages/shared/src/commercialEngineModels.ts` 的 OpenAI-compatible 解析逻辑。
- `owned_by` / `provider` 只作为展示来源，不作为路由权威。
- 模型 ID 必须原样传给 dev2；dev2 再按后台白名单决定是否允许。

验收：

- 模型列表请求地址不出现真实 upstream。
- 模型列表响应不包含上游 API key 或真实 upstream Base URL。
- allowlist 非空时，列表和请求都受 allowlist 限制。

### Phase 2：模型注入到 ai-engine

目标：用户选择的模型 ID 正确进入 codex app-server。

路径：

```text
modelSelection.model
  -> ProviderSessionStartInput
  -> CodexAdapter.startSession()
  -> CodexSessionRuntime spawn
  -> CODEX_MODEL / provider config
```

要求：

- `MYIDE_IDE_JWT` 只注入 app-server/ai-engine 子进程。
- shell include list 不能包含 `MYIDE_IDE_JWT`。
- `CODEX_OPENAI_BASE_URL` 和 `OPENAI_BASE_URL` 只能是 dev2 `/v1`。

### Phase 3：用量和限额闭环

目标：客户端展示 dev2 本地计费状态。

- `GET /api/v1/auth/me` 读取用户、余额和 provider。
- `GET /ide/api/usage` 读取 5 小时窗口、每周窗口、token、cache token 和实际花费。
- 前端 usage gate 只做发送前提示；用户仍可能被 dev2 后端最终拒绝。
- 错误码映射要识别余额不足、窗口超限、模型不可用和撤销 token。

### Phase 4：安全验证

必须覆盖：

- IDE JWT 撤销后，`/v1/*`、`/ide/api/*` 和 `/api/v1/auth/me` 返回 401。
- 普通 Web API 不接受 `token_use=ide`。
- 真实 upstream Base URL 和 API key 不进入前端状态、日志、trace 或错误响应。
- 余额不足时 dev2 在请求 upstream 前拒绝。
- usage 缺失时 dev2 不写成功扣费。
- 重复 `Idempotency-Key` 不重复请求 upstream，也不重复扣费。

## 不在本期范围

- 自研多渠道模型网关。
- OpenAI/Claude/Gemini 协议转换。
- 客户端直连第三方 upstream。
- 迁移 sub2api 旧余额、旧 usage 或旧字段。
- 用户侧自助充值和自助改套餐。
